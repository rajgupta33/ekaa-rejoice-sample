# EKAA REJOICE — THE ART OF REJOICING
## Premium, Mobile-First, Single-Page Website: Creative Direction + UX + Content + SEO + Development Specification

**Document version:** 1.0  
**Research date:** 14 November 2026  
**Deliverable:** A build-ready website specification in Markdown (not the finished website)  
**Brand:** Ekaa Rejoice, part of the Ekaa brand family  
**Market:** Dubai, UAE, subject to confirmation of the precise service coverage  
**Primary conversion:** Service-specific WhatsApp enquiries  
**Design ambition:** Editorial event-luxury meets joyful, art-directed motion. Elegant on desktop; unusually effortless on mobile.

> **The central creative idea:** An Ekaa Rejoice event is not simply a decorated venue. It is a feeling made visible. The site should make visitors *feel* that transformation before they ask for a quote.

# 01. Executive creative brief

## The project in one sentence

Build a **single-page, mobile-first, SEO-conscious event styling website** with a premium **three-slide zoom-animated hero**, visually rich service navigation, an authentic project gallery, engaging but lightweight 3D-inspired details, refined About and Contact sections, and **direct WhatsApp calls to action for every service**.

## What this website IS

- One primary scrollable URL with anchored sections, not a 3-page website.
- A portfolio and lead-generation experience for private celebrations, expressive decor, and business events.
- A sophisticated brand extension of the supplied Ekaa Rejoice logo.
- A website that communicates distinctive visual taste through imagery, layout, editorial typography and motion.
- A fast mobile landing experience for visitors arriving from Instagram stories, reels, sponsored ads, direct links and Google Search.

## What this website is NOT

- Not a generic balloons-and-confetti template.
- Not a heavy 3D game that makes a mobile user wait for a page to load.
- Not an ecommerce store or a long multi-step booking platform.
- Not a directory of disconnected event pages.
- Not a portfolio that presents generic stock or AI-generated work as real client events.
- Not a page full of unverified awards, client testimonials, project counts or invented package prices.

## Prioritized goals

1. **Visual impact in the first two seconds:** full-bleed, art-directed imagery, purposeful typography, brand clarity.
2. **Quick service discovery:** most visitors should locate the right service in one or two swipes.
3. **Frictionless WhatsApp:** tapping any service's action opens WhatsApp with that service already named in the message.
4. **Trust:** real photography, genuine event categories, straightforward planning process, actual contact details.
5. **Mobile sophistication:** thoughtful cropping, large touch areas, bottom CTA, seamless section flow.
6. **Organic discovery:** Dubai-centric service-language, accurate metadata, structured data, crawled text and useful FAQ content.
7. **Performance and accessibility:** smooth experience on midrange mobile devices and slower networks.

# 05. Brand identity and visual design system

## Design concept: “Sculpted Joy”

Imagine an art-directed luxury editorial magazine about celebrations, where the website occasionally lets a pearl balloon, translucent ribbon, glass sphere, or sculpted color gradient escape the page. Movement should feel airy, carefully staged and premium rather than busy.

### Non-negotiable logo treatment

- Use the **supplied Ekaa Rejoice logo** faithfully; do not redraw the symbol or replace its typography.
- The current uploaded logo is a compact **150 × 150 px raster image**. Source a high-resolution PNG with transparency or, preferably, an official SVG/vector master before production.
- On ivory sections, use the primary full-color logo with adequate spacing.
- On image-heavy hero headers, place it on a subtle translucent/ivory backdrop if necessary; never make it disappear into the photograph.
- Do not invent logo variants or introduce a non-official Ekaa Rejoice emblem.
- Build a favicon/app icon only from the **approved** original artwork, prepared by a designer.

### Typography

- **Display:** `Cormorant Garamond` (or approved alternative `Bodoni Moda`) for cinematic, emotionally expressive headlines.
- **UI / body:** `Manrope` for legible, contemporary interaction text.
- Use **two families maximum**. Preload only the weights actually used. Host font files locally where appropriate.

Suggested sizes (fluid using `clamp` in CSS):

| Type | Mobile | Desktop | Notes |
|---|---:|---:|---|
| Hero headline | 48–64 px | 88–124 px | 2–4 lines; excellent line breaks |
| Section headline | 38–48 px | 64–86 px | Editorial serif |
| Card title | 24–30 px | 28–36 px | Brief and crisp |
| Body text | 15–17 px | 17–19 px | 1.5–1.65 line height |
| Eyebrow / overline | 10–12 px | 11–13 px | Uppercase / tasteful letter spacing |
| Buttons | 14–16 px | 14–16 px | Medium/semibold |

### Surfaces and borders

- Use no more than **three** surface styles: ivory editorial; soft frosted glass over imagery; warm pearl-gradient showcase.
- Main card radius: 20–28 px mobile, 24–36 px desktop.
- Buttons: rounded pill (50+ px height) or gentle 14–18 px rounded rectangles; choose one predominant approach.
- Fine, quiet strokes; layered soft shadows. No heavy neon glow.
- Very light film grain in selected backgrounds for tactile editorial depth; do not compromise text clarity.

### 3D-inspired visual elements

**Recommended art assets:** 3D translucent glass bubbles, blush/champagne balloons, sculpted satin ribbon, floating chrome confetti, and soft abstract droplets inspired by the logo's celebration colors.

**Placement:** 1–2 designed objects in the hero, 1 editorial break, 1 subtle contact orb. Use negative space generously.

**Execution:** Prefer pre-rendered transparent WebP/AVIF images or lightweight SVG plus GPU-friendly CSS transforms. If a real WebGL/Spline/Three.js object is approved, load it **below the fold** only and show a static replacement on touch devices, reduced-motion settings and constrained networks. Hero readability and loading speed always take precedence.

### Imagery

The photographic style must feel like an intimate luxury magazine:

- Real project photography, polished but authentic.
- Deliberate wide photos plus tight styling details: ribbons, place settings, balloon installations, light, textures, reactions.
- Warm daylight or professionally designed event lighting, not over-filtered imagery.
- Variation across family celebrations and corporate events.
- Reserve clean negative-space regions for typography on hero crops.
- Every hero has a **separately art-directed mobile crop**, not a desktop image arbitrarily squeezed into a portrait container.

# 06. The signature three-slide cinematic hero (highest-priority feature)

**Interpretation of the request:** The site has **three hero slides** within the **one-page website**. Each is a different story. All three should feel like a continuous premium brand film, without forcing video playback.

## Desktop composition

- Height: `min(92svh, 920px)`, with a practical minimum around 660px for common laptop viewports.
- Full-bleed imagery with a nuanced left-to-right dark/purple-brown fade for readable white copy.
- Header overlays the hero at the top with approved logo treatment.
- Text column: 40–48% width, left aligned; photo focal subject on right.
- Bottom: `01 / 03` slide indicator, discreet 3-segment progress track, previous/next controls and “Scroll to Explore” cue.
- A translucent sculptural element may float near one far edge but must not cover people, copy, or CTAs.

## Mobile composition

- Hero height: approximately `85–94svh` according to viewport, capped to avoid awkward UI overlap; support small devices and landscape gracefully.
- Art-direction target: portrait **4:5 or 9:16** image source, with subject above/right or balanced behind a reserved lower text area.
- Copy anchored in the **lower-middle**, above navigation dots, CTA and safe-area inset. Do not put crucial copy under the browser's address bar.
- One primary CTA in the hero (`Plan My Event`), one text link (`Explore Our Work`).
- Swipe left/right works; dots/buttons remain available. Don't hijack vertical scrolling.
- Preserve readability on a 320px viewport; no text clipping or horizontal overflow.

| **01** | **Signature Celebrations** | Stunning authentic birthday or milestone setup; blush/ivory/champagne palette; guests or personal details; subtle soft-focus depth | **The Art of Rejoicing.** | “From intimate birthdays to unforgettable milestones, we turn your moments into beautifully designed experiences.” | **Plan a Celebration** → WhatsApp with `Birthday Celebrations / Private Celebration` |

**Small eyebrow above the headline:** `EKAA REJOICE • DUBAI` (only if the team approves Dubai service-area wording).

**Text contrast:** a sufficiently dark variable overlay behind text; never rely on a photo being dark enough on every screen.

### Motion design blueprint

**All times are initial design specifications and must be tuned by visual QA.**

1. **Initial load:** Slide 1 photograph and headline appear immediately with no full-screen loading animation. First frame must never be blank.
2. **Headline reveal:** after image paint, each line rises 12–18 px, settles over 550–750 ms with an ease-out curve; no excessive character-by-character animation.
3. **Ken Burns image zoom:** image scale `1.00 → 1.07` over **7.0 seconds**; slow and almost imperceptible. Optional slight 1.5% lateral drift only on desktop.
4. **Slide hold:** roughly **6.5–7 seconds** per slide. Transition image with **700–900 ms** crossfade; avoid flash/white gaps.
5. **New slide text:** gently crossfades/reveals on transition, with a stagger of 80–130 ms for headline/body/CTA.
6. **Progress segments:** thin, understated lines show current progress and allow click/tap navigation.
7. **3D object:** a pre-rendered balloon or ribbon may rotate 2–4 degrees / drift 4–8 px on a 6–9 second loop, not bounce conspicuously.
8. **Interaction rules:** manual next/prev/dot selection resets progress. Do not advance during swipe drag, while CTA receives focus, when tab is hidden, or when reduced-motion preference is active. On hover/focus within the slider, pause automatic movement where feasible.
9. **Reduced motion:** zero Ken Burns; no floating/scroll-linked animation; slide changes via instant switch or very short low-motion fade. Keep all information and controls usable.
10. **Mobile/network fallback:** first hero uses a lightweight preloaded still; optional decorative 3D effects do not block rendering. Reduced-data mode should avoid heavy effects.

### Hero states / testing checklist

- Slide 1 is the meaningful LCP image and must receive appropriate priority.
- Auto-play never disables manual navigation.
- Use semantic buttons with labels such as `Go to slide 2 of 3`.
- Arrow keys operate focused carousel, with focus treatment and live-region announcements that are not noisy.
- Text remains readable throughout the zoom and on every breakpoint.
- Safe-area insets handled on devices with a notch.
- Buttons are tappable without accidentally navigating a slide.
- Every hero has one crisp, service-relevant path to WhatsApp.
- The overall first-screen experience remains clear without JavaScript.

### Visual anti-patterns

Do **not** use: huge confetti explosions on every transition, a full-screen cinematic preloader, flashing gradients, auto-playing unmuted music, autoplay video that prevents LCP, dizzying 3D camera spin, duplicated text images, random celebrity/event photographs, illegible white-on-light headings or desktop-only hero compositions.

| Hero zoom | 7 seconds | `scale(1.0)` → `scale(1.07)` |
| Gallery dialog | 180–300 ms | Instant close and focus return |
| Continuous 3D accents | 6–9 seconds | Tiny motion and graceful static fallback |

Do not animate layout-affecting dimensions unnecessarily. Prefer `transform` and `opacity`, and ensure JavaScript-driven motion never blocks reading or tapping the interface.

# 13. Performance, accessibility, privacy and security

## Performance targets

Google's Core Web Vitals guidance favors strong real-user mobile outcomes:

| Metric | Target at the 75th percentile | Implementation consequence |
|---|---|---|
| **Largest Contentful Paint (LCP)** | **≤ 2.5 seconds** | Show first hero immediately; prioritize correct first image |
| **Interaction to Next Paint (INP)** | **≤ 200 ms** | Avoid huge animation scripts, unnecessary hydration and long tasks |
| **Cumulative Layout Shift (CLS)** | **≤ 0.1** | Reserve image dimensions and fixed CTA space; preload/fonts carefully |

**Extra proposed engineering budgets (aspirational, validate with actual tools):** mobile first hero ~150–300 KB optimized if visual quality permits; desktop ~300–550 KB; compress and defer later hero slides; prefer less initial JavaScript over unnecessary plugins. Aim for a Lighthouse mobile performance score of 90+ where realistically achievable, but judge actual measured Core Web Vitals rather than a synthetic score alone.

### LCP and slider-loading checklist

- The initial hero image must be discoverable early in HTML; give it `fetchPriority="high"` or equivalent.
- Avoid making the first hero a CSS background hidden until hydration if it delays image discovery.
- Load offscreen hero slides with normal/lower resource priority and prefetch near slide transitions as needed; do not prioritize all three hero images equally at first paint.
- Use correct `sizes` and responsive `srcset` for mobile/desktop.
- Explicit `width`/`height` or stable `aspect-ratio` on images to avoid CLS.
- Reserve space for fonts, gallery cards, and fixed mobile buttons.
- Keep below-fold 3D and gallery media lazy.
- Do not load embedded Instagram widgets or heavy external embeds during first paint.
- Use static fallback artwork if advanced effects fail to load.
- Audit on midrange Android + mobile network throttling, not only fast desktop devices.

## Accessibility commitment

Target **WCAG 2.2 AA**.

- Headings in logical hierarchy and main landmark.
- Meaningful links, buttons, `aria-label`s and keyboard navigation.
- **Aim for ≥44×44 px touch targets** for primary controls, exceeding WCAG 2.2's 24×24 CSS pixel minimum/spacing criterion.
- Strong visible focus outlines; adequate text/background contrast.
- Correct announcement and control semantics for carousel and tabs.
- No text baked into photos when that is the only available text.
- No color-only communication for selected tabs or form errors.
- Respect `prefers-reduced-motion` and offer manual carousel control.
- Avoid autoplay audio and animated background video that obstructs content.
- At 200% zoom and 320px widths, text remains usable and no important content clips.
- Basic accessibility tests with keyboard, VoiceOver on iOS, TalkBack on Android and automated accessibility tools.

## Privacy and technical hygiene

- If Google Analytics or any other tracking is deployed, disclose it appropriately and implement consent controls where required by applicable law/circumstances.
- Do not pass visitor-written messages, phone numbers, free-form event notes or other personally identifying details into analytics events.
- The guided WhatsApp form should assemble a link locally; don't silently submit personal details to the website server.
- Use HTTPS, correct CSP/security headers as supported, controlled dependencies and restricted access to any optional CMS.
- Include actual privacy policy with contact details, what is collected, analytics/embedded services used and how enquiries are handled. Obtain legal review for compliance as appropriate.
- Respect browser choice and avoid manipulative or misleading consent interfaces.

# 14. Analytics and measurement plan

The website's goal is **qualified WhatsApp conversations**, not mere carousel views. Without actual WhatsApp CRM or business integrations, the website can measure **link clicks**, but it **cannot honestly claim a conversation was started or a booking was completed**.

## Recommended events

| Event name | Trigger | Safe useful properties |
|---|---|---|
| `hero_slide_view` | Each hero slide becomes active | `slide_id`, `view_mode` |
| `hero_cta_click` | User clicks hero CTA | `slide_id`, `service_id` |
| `service_filter_select` | Visitor changes category | `category_id` |
| `service_whatsapp_click` | User opens a service enquiry | `service_id`, `placement` |
| `gallery_project_open` | User opens project details | `project_id`, `category` |
| `gallery_whatsapp_click` | User enquires about similar work | `service_id`, `project_id` |
| `contact_whatsapp_click` | User clicks final CTA | `placement` |
| `enquiry_builder_continue` | User completes optional WhatsApp prefill UI | `service_id` only, not entered details |

**UTM/campaign tracking:** rely on landing-page attribution in consented analytics, without injecting unnecessary campaign details into the user's WhatsApp message.

## KPIs to review after launch

- Mobile vs desktop traffic split.
- WhatsApp CTA clicks by service.
- WhatsApp click-through rate: unique clickers / appropriate sessions (define it consistently).
- Top service categories.
- Hero slide clicks and manual navigation (diagnostic, not vanity-only).
- Gallery engagement, scroll depth and FAQ interactions.
- Search Console impressions, clicks and qualified search queries.
- Actual qualified inbound requests and conversions tracked manually in WhatsApp Business / CRM if adopted (not inferred from webpage clicks).

**No invented benchmarks or guaranteed conversion uplifts.** Create a baseline after launch, improve based on observed visitor behavior.

# 17. Two implementation options

## Recommended: “Editorial Premium” (best trade-off)

- Three photo-led animated hero slides with CSS transforms/crossfades.
- One or two lightweight pre-rendered 3D accents for dimensionality.
- Art-directed custom cards, gallery, tasteful filters and fixed mobile CTA.
- Strong real-event photography and conversion flows.
- No heavy continuous WebGL scene.

**Why this is the default:** It delivers premium impact, more reliable mobile responsiveness, faster load times and easier maintenance while still feeling visually distinctive.

## Optional: “Cinematic Showcase” (higher production complexity)

Includes the recommended build plus an **optional** scroll-responsive 3D centerpiece in the editorial interlude, only if supported by business goals and media budget. WebGL loads after the first screen, never blocks the hero, and has an equivalent static fallback.

**Do not choose the heavier option merely because “3D” sounds premium.** A great event photograph and brilliantly composed typography are more persuasive than a poorly performing moving model.
